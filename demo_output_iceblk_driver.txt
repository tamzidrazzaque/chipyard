  # Already running: F2 sim in tmux, Linux booted, SSH tunnel on 25050, OpenOCD up

  # 1. Set breakpoint on iceblk driver (via OpenOCD telnet)
  echo "rbp all" | nc -q 2 localhost 4444
  echo "bp 0xffffffff013746e6 2 hw" | nc -q 2 localhost 4444
  echo "resume" | nc -q 2 localhost 4444

  # 2. Trigger block I/O from userspace
  ssh -i ~/firesim.pem ubuntu@192.168.1.203 \
    'tmux send-keys -t firesim "dd if=/dev/iceblk of=/dev/null bs=4096 count=1" Enter'

  # 3. Wait ~10s, then verify breakpoint hit
  sleep 10
  printf "halt\nreg pc\n" | nc -q 5 localhost 4444
  # -> pc = 0xffffffff013746e6  (iceblk_rq_handler)

  # 4. Single-step through driver code
  printf "rbp all\nstep\nreg pc\nstep\nreg pc\nstep\nreg pc\n" | nc -q 15 localhost 4444
  # -> steps through prologue into blk_mq_start_request

  # 5. Resume
  echo "resume" | nc -q 2 localhost 4444

================================================================================
H. KEY TECHNICAL POINTS FOR PRESENTATION
================================================================================

  1. This is the first known demonstration of live JTAG kernel debugging
     of a custom device driver on a FireSim FPGA simulation.

  2. The direct JTAG path required a clock adaptation: the standard Rocket
     Chip JTAG TAP uses negedge-clocked registers (for TDO output and
     instruction latching), which is incompatible with FAME-1 transformation.
     We converted these to posedge-only logic with combinational TDO output.

  3. The iceblk driver is a real FireSim custom block device driver that
     communicates with the hardware model via MMIO. The breakpoint hits
     at the exact entry point where the kernel hands a block I/O request
     to the driver.

  4. The debug path: OpenOCD → remote_bitbang TCP → JTAGBridge (FPGA MMIO)
     → JTAG TAP → Debug Module → hart debug registers.

  5. GDB can load module symbols (iceblk.ko) at the runtime load address
     from /proc/modules, enabling source-level debugging of loadable
     kernel modules.
